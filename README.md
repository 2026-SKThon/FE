# 🌡️ ON-e

> 아두이노 기반 저가형 체온 센서로 우리 아이의 상태를 실시간으로 지켜보고, 위험 상황에는 AI가 판단 · 설명 · 병원 안내까지 이어주는 IoT 영유아 돌봄 서비스

## 📖 서비스 소개

ON-e는 **아두이노 기반 저가형 체온 센서를 활용하여 영유아의 체온을 실시간으로 모니터링하고, 이상 징후 발생 시 보호자의 대응을 돕는 IoT 헬스케어 서비스**입니다.

맞벌이 가정에서 발생할 수 있는 상시 돌봄 공백과 초보 부모가 겪는 위기 상황 판단 및 병원 커뮤니케이션의 어려움을 해결하고자 합니다.

고가의 스마트 체온 패치 대신 **아두이노 기반의 저가형 센서**를 활용하여 접근성을 높이고, 단순히 현재 체온만 보여주는 것이 아니라 **체온 · 아이의 나이 · 체온 상승 속도 · 투약 이력**을 종합하여 병원 방문 필요성을 판단합니다.

위험 신호가 감지되면 보호자가 병원에서 활용할 수 있는 **증상 설명 스크립트**를 자동으로 생성하고, 보호자 위치를 기준으로 현재 이용 가능한 **주변 병원 · 응급실**까지 안내하여 판단이 실제 행동으로 이어질 수 있도록 돕습니다.

- **아두이노 체온 센서**를 통한 실시간 체온 측정
- 체온 · 나이 · 상승 속도 · 투약 이력을 활용한 **AI 복합 상황 판단**
- 위험 구간 진입 시 보호자에게 **즉시 알림 제공**
- 측정 데이터와 복약 이력을 기반으로 **병원 방문용 증상 설명 스크립트 자동 생성**
- 보호자 위치를 기반으로 **주변 병원 · 응급실 안내**
- 아이 프로필, 기기 연결, 알림 기준 등 **돌봄 환경 관리**

ON-e는 위험 상황을 알려주는 것에서 끝나지 않고, 보호자가 상황을 이해하고 실제 병원 방문까지 빠르게 이어갈 수 있도록 **측정 → 판단 → 설명 → 행동**의 과정을 하나의 서비스로 연결합니다.

## ✨ 주요 기능

| 기능                           | 설명                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------ |
| 🌡️ **실시간 체온 측정 연동**   | 아두이노 센서 데이터를 보호자 서비스에 실시간으로 전달하여 아이의 체온 변화를 확인할 수 있습니다.      |
| 🚨 **위험 상황 알림**          | 체온이 위험 구간에 진입하거나 이상 징후가 감지되면 보호자에게 즉시 알림을 제공합니다.                  |
| 🤖 **AI 복합 상황 판단**       | 체온, 나이, 체온 상승 속도, 투약 이력을 함께 분석하여 병원 방문 필요성을 안내합니다.                   |
| 💊 **복약 기록 관리**          | 아이의 복약 기록을 입력하고 복합 상황 판단과 증상 설명 스크립트 생성에 활용합니다.                     |
| 📝 **증상 설명 스크립트 생성** | 측정된 체온 데이터와 복약 이력을 기반으로 보호자가 병원에서 그대로 활용할 수 있는 설명문을 생성합니다. |
| 📈 **발열 기록 확인**          | 이번 발열의 체온 변화 그래프와 기록을 확인하여 아이의 상태 변화를 파악할 수 있습니다.                  |
| 🏥 **병원 · 응급실 안내**      | 보호자 위치를 기준으로 주변 병원 · 응급실을 지도와 목록으로 안내하고 병원 상세 정보를 제공합니다.      |
| 👶 **돌봄 설정 관리**          | 아이 프로필, 기기 연결, 알림 기준, 보호자 프로필 등 서비스 이용에 필요한 돌봄 환경을 관리합니다.       |

## 🎯 Git Convention

- 🎉 **Start** : Start New Project `[:tada:]`
- ✨ **Feat** : 새로운 기능 추가 `[:sparkles:]`
- 🐛 **Fix** : 버그 수정 `[:bug:]`
- 🎨 **Design** : CSS 등 사용자 UI 디자인 변경 `[:art:]`
- ♻️ **Refactor** : 코드 리팩토링 `[:recycle:]`
- 🔧 **Settings** : 설정 파일 수정 `[:wrench:]`
- 🗃️ **Comment** : 필요한 주석 추가 및 변경 `[:card_file_box:]`
- ➕ **Dependency/Plugin** : 라이브러리 추가 `[:heavy_plus_sign:]`
- 📝 **Docs** : 문서 수정 `[:memo:]`
- 🔀 **Merge** : 브랜치 병합 `[:twisted_rightwards_arrows:]`
- 🚀 **Deploy** : 배포 관련 작업 `[:rocket:]`
- 🚚 **Rename** : 파일 및 폴더 이름 수정 `[:truck:]`
- 🔥 **Remove** : 파일 삭제 `[:fire:]`
- ⏪️ **Revert** : 이전 버전으로 롤백 `[:rewind:]`

## 🌲 Branch Convention

- `main` : 배포 가능한 브랜치
- `develop` : 개발 브랜치
- `feat/#이슈번호/명칭` : 새로운 기능 개발 브랜치
  - 예시 : `feat/#12/temperature`
- `ui/#이슈번호/명칭` : UI 작업 브랜치
  - 예시 : `ui/#12/home`
- `docs/#이슈번호/명칭` : 문서 작성 및 수정 브랜치
  - 예시 : `docs/#12/readme`
- `api/#이슈번호/명칭` : API 연동 작업 브랜치
  - 예시 : `api/#12/hospital`
- `refactor/#이슈번호/명칭` : 리팩토링 작업 브랜치
  - 예시 : `refactor/#12/component-structure`

## 🌊 Flow

1. Issue 생성
2. 최신 `develop` 브랜치에서 작업 브랜치 생성
3. 기능 개발 및 커밋 진행
4. `develop` 브랜치로 Pull Request 생성
5. 코드 리뷰 진행
6. 리뷰 완료 후 `develop` 브랜치로 병합
7. 병합 완료 후 작업 브랜치 삭제
